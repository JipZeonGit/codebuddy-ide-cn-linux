## 新增与变动模块分析与移植处理

### 1. `@tencent/qimei-node-unified@1.2.3`

- **类型**：腾讯专有的私有 Node.js SDK，用于取代旧版 `@tencent/qimei-node` 风控设备指纹体系。
- **架构设计**：
  - 旧版 `@tencent/qimei-node` 采用的是传统的源码与多平台条件编译/加载架构，且自带 Windows/macOS 两个平台独立的源文件目录（`src/mac/`、`src/win/`）以及 build 构建目录。在非 Windows/macOS 平台上调用时会通过 JS 层的平台校验静默返回 `this.available = false`。
  - 新版 `@tencent/qimei-node-unified` 则是官方提供的**免安装/单体化（Self-contained）**预编译多平台分发包，将所有编译好的 macOS/Windows 原生 `.node` 库与 Windows `qimei.dll` 集中放置在包内的 `bindings/` 目录下。
- **加载校验与运行分析**：
  - 其入口 `index.js` 在加载 native 二进制时，在 `loadNative()` 函数首行进行平台与架构校验，强制匹配 `darwin-arm64`、`darwin-x64`、`win32-x64`。
  - **在 Linux (linux-x64) 下执行时**，`loadNative()` 会直接抛出 `Error: @tencent/qimei-node-unified: platform linux-x64 is not supported.` 异常。
  - 上游的主进程服务层 `qimei-main-service.js` 使用 `try-catch` 结构包裹了这一加载逻辑。捕获到该错误后，会判定服务在当前宿主不可用，并在控制台记录 `[QimeiMainService] failed to load '@tencent/qimei-node-unified'` 警告后**优雅降级退出**，并不会导致主进程崩溃。
- **移植处理**：
  - 因为 Linux 无法加载 `bindings/` 目录下的 Darwin 和 Win32 原生二进制，我们直接在 `remove_known_wrong_platform_modules()` 阶段清空该整个 `bindings/` 目录。
  - 保留外层 `index.js` 和 `package.json` 以维持依赖树完整，当 Electron 启动时，代码能够通过 `require('@tencent/qimei-node-unified')` 正常引入，随后在实例化调用时触发不支持的平台异常，并由主进程的 `try-catch` 捕获拦截，完成无缝适配与优雅降级。
